Decision needed “Highest dollar amount” has more than one possible meaning

The site currently ranks by displayed bid-side notional calculated from orderbook levels. This is an explicit project metric, not an official Kalshi event-level dollar-volume field. Executed trading turnover or open interest would be different measures. The ranking should not be used as a proxy for actual dollars traded unless that definition is intentionally accepted.

Needed: choose the intended metric and time period. The 24-hour volume column remains a contract count.

Plain “gas” matches may include non-retail gas contracts, and golf terms such as “the Masters” can be ambiguous; both cases are noted in the methodology.

Resolution rule “Determined” is not the same as fully settled

Kalshi documents a lifecycle in which a result is set at determination and can be disputed before settlement is finalized. The watchlist shows the exact status and raw result separately; it does not silently treat all posted results as a paid-out, final state.

Needed: decide whether review should stop when the result is determined or only after Kalshi reports finalized status. The current list remains visible until manually removed.

Local-only Watchlist and proposal selections are stored in this browser

Tracked events and selected suggestions use browser local storage. They are not synced across devices, backed up, or checked while the page is closed. The resolution page can fall back to Kalshi’s historical-market endpoint, but the full historical handoff has not been tested against live responses here.

Needed: if durable monitoring is required, approve retention duration, hosting, database, export, and alert-delivery behavior.

Chart scope Seconds history is ephemeral; official candles are minute/hour/day bars

The 30-second chart samples every five seconds while the page is open and has no preloaded history. The other ranges use documented one-minute or one-hour candles. Background tab throttling, API gaps, and no-trade periods can result in missing observations.

Needed: decide if seconds-level history must persist, and if so approve a storage/streaming service. The WebSocket handshake is authenticated per Kalshi docs.

Outcome scope Not all market results are necessarily YES or NO

The project only includes open binary markets in its live leaderboard, but Kalshi’s result schema also documents other outcome forms, including scalar results. The watchlist preserves any raw result instead of coercing it into a YES/NO label.

Needed: confirm whether future watchlists should include only binary markets or include other market types with separate result displays.
