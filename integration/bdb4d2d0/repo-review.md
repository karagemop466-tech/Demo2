## 3. Defects found in this review (all fixed or flagged)

### 3.1 Main was red: PR #35 hand-edited generated pages — FIXED (commit `6df5c9f`)
`Build and check the site` failed on `main` at 12:57:58 and 13:02:27 (run
`44740812355`): *"Fail if regenerating produced a diff (pages must match the
generator)"*. Cause: session `e36292f6` (PR #35) edited `index.html`,
`pages/flagged.html`, `pages/suggestions.html`, `pages/verification.html`
directly without updating `tools/build_site.py` / `tools/build_content.py`.
Their content also contained a shell-expansion corruption (`/bin/bash.10`
where `$0.10` was meant — `$0` expanded inside a heredoc).
Fix: ported the sharp-jump feature into the generators, fixed the corruption,
regenerated, and added the brief-required "possible context (unverified)"
news-search links per jump row. Verified by re-running both generators
(diff = intentional improvements only) and `tools/check.py` (clean).

### 3.2 `data/snapshot.json` / `data/resolutions.json` never landed on main — FLAGGED (F15), fix in flight
`pages/resolutions.html` and `index.html` fetch `data/resolutions.json` /
`data/snapshot.json` (via `assets/site.js` `KR.getJSON`) — confirmed on the
deployed site 2026-11-20 13:2x UTC: *"Could not load data/resolutions.json →
HTTP 404"* and *"Data snapshot could not be loaded: data/snapshot.json → HTTP
503"*. Root cause: `tools/collector.py` (the only writer of those files) has
**never completed successfully on main** — the single main run
(`44728913873`, 11:35 UTC) died at step *"Collect demo snapshot"* (log body
not retrievable from this sandbox — GitHub blob storage egress denied, EOF).
Session `6332d7d3` has a rewritten collector (+614 lines) running green on
its own branch (`arena/6332d7d3-demo2`, runs at 13:02 and 13:10 UTC) — that
session's PR is the proper fix; this session dispatched
`Refresh Kalshi demo data` on `main` (run `44744689706`) to test the current
code again. If it stays red, the missing files are flagged on the site (the
pages already show honest "no values are invented" empty states) and the
handoff to `6332d7d3` is logged in COORDINATION.md.
`tools/analyze.py` also references `data/resolutions.json` in the `source`
string of `data/analysis.json` — consistent with the missing file, not a
fabrication (all values null/blank by design until authenticated).

### 3.3 Browser-side credential prompts on a public static host — FIXED (commit `49e706e`, flag F14)
`assets/app.js` still shipped orphaned WebCrypto signing/order code
("Enter demo API Key ID + private key (stored only in this browser)") wired to
element ids no page contains, and `live/trading.html` Mode B asked the user to
paste a demo private key. PR #6 (session `22b4f0cb`, stale >60 min — taken
over per the board's rule) raised exactly this. Fixed: signing code removed;
Mode B form disabled on the deployed copy behind a reversible notice pointing
at the gated Actions path. `node --check` passes; `tools/check.py` secrets
scan clean.

### 3.4 Instrument-panel rendered URL *patterns* as clickable placeholder links — FIXED (commit `79fecce`)
`instrument-panel/site/{analysis,verification}.html` contained
`href="…/markets?series_ticker={ticker}…"`-style links (found by
`tools/check_live_links.py`). Root cause: `ext()` in
`instrument-panel/tools/site_build_core.py` turned the collector's `ENDPOINTS`
templates into anchors. `ext()` now renders patterns as `<code>`; the
analysis source line keeps the official `get-markets` docs link.
Verified: full rebuild + `check_live_links.py` → *"no broken internal links,
no duplicate ids, no placeholders"*.

### 3.5 `data/history_instrument/*.json` tick rows carry no source URL — FLAGGED (F16)
Sample rows (`{t, lp, yb, ya, oi, v}`) and the file header have no endpoint
URL. Provenance rests on `instrument-panel/tools/kalshi_collect.py` and the
Live page's prose. Suggested fix (logged for the owner): add a file-level
`source`/`endpoints` field when writing history samples. Not changed here to
avoid fighting the 15-minute `pages.yml` rewriter before the fix lands.

### 3.6 Four data pipelines commit into one `data/` directory — FLAGGED (F17)
`refresh-data.yml` (10 min), `pages.yml` (15 min), `data-refresh.yml` (2 h),
`collect.yml` (2 h) can race and revert each other's files (two same-named
workflows, "Refresh Kalshi demo data" vs "Refresh Kalshi data", add
confusion). Files are all evidence-grade, but the layout invites merge churn.
Recommendation on the suggestions register: one refresher, one schema,
versioned history.

### 3.7 `data/resolved.json` 200-row window contains only `result=no` rows — NOTED
Live re-check shows the file is verbatim-correct per row (verification.md §3),
but the window sampled only strike markets that resolved **no** (1,423 no /
178 yes in the larger `dashboard_instrument.json` set). Readers comparing the
two files should not treat `resolved.json` as representative — its `note`
field already scopes the window. No value was changed.
