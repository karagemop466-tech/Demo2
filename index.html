Sharp price moves — jumps ≥ $0.10 between consecutive price points

Each red marker on the chart is a move of $0.10 or more between two consecutive points. The API returns price and volume but not the news or event behind a move, so the cause is not inferred — each row links to the market's own page on Kalshi and is flagged cause unverified. Live alerts — every move of $0.10 or more, in two scrolling feeds

How these feeds work. The browser polls the public Kalshi demo Trade API directly (GET /markets?tickers=…&status=open — Get Markets) and raises a line when a contract price moves $0.10 or more in either direction. Two official signals are compared: the API's own previous_price_dollars against last_price_dollars, and the price seen on the previous poll against the price now — so a move cannot slip through between two polls. Left feed: every such move. Right feed: the moves the ranking model likes. The WebSocket ticker channel is deliberately not used: the official docs require an authenticated WebSocket handshake even for the public channels, and this site never asks a visitor for a private key. The API returns prices and volumes but no news feed, so the cause of a move is never asserted — every line links to that market's own Kalshi endpoint and carries the cause unverified label.

Model — documented heuristic, not a prediction:
score = 0.45·min(|Δ|/0.30,1) + 0.25·min(est. $vol/50,000,1) + 0.15·min(OI/5,000,1) + 0.15·(1 − min(hours to close/72,1))
Inputs (all official or clearly labelled): |Δ| = the move in contract dollars · est. $vol = the labelled estimate volume_fp × last_price_dollars · OI = official open_interest_fp · hours to close = official close_time. The score only ranks alerts against each other; it is not a probability, and no profit is claimed.

Markets ranked by estimated dollar volume

What "highest dollar amount" means here. The Trade API has no single dollar-volume field. Every row therefore shows the raw official fields (volume_fp, open_interest_fp, last_price_dollars) and one clearly-labelled estimate: volume_fp × last_price_dollars. A second estimate uses the official 24-hour volume instead of the lifetime one (volume_24h_fp × last_price_dollars), which is the closer match to “currently active” markets. Rows missing lifetime volume_fp (top-event lead markets) show a blank there and a labelled 24h estimate beside it. Coverage: the demo exchange returns far more open in-scope markets than GitHub accepts in one published file (hard limit 100 MB — a 111.97 MB snapshot was rejected on 2026-11-20), so the collector publishes, per topic, all markets of the highest-value events by the estimate above plus the highest-value individual markets, and records exactly what was left out in the published_subset block of data/snapshot.json.
