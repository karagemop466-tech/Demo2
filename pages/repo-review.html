3 · Findings in the code

IDWhereFindingAction
C1assets/app.js (previous revision)The chart was fed only from browser polling, so it showed nothing before the page was opened and could not render a multi-day view.Replaced with the official candlestick endpoint plus live polling (suggestion S2).
C2assets/app.js (previous revision)Several API fields were read from names that do not exist in the current demo response (volume, last_price, yes_bid, liquidity), so cells rendered blank even when the response carried the value.Now reads the fixed-point field names actually present in the response (volume_fp, last_price_dollars, yes_bid_dollars, liquidity_dollars).
C3assets/app.js (previous revision)On a failed API call the table was replaced with an error message that also cleared the page of previously loaded rows.The failure path now keeps the last good data and reports the failure in the status line only.
C4assets/app.js (previous revision)The chart canvas was sized from a fixed pixel height while the CSS gave it a percentage height, so the drawing surface did not match the displayed box on high-density screens.The canvas is now sized from its client box and scaled by the device pixel ratio.
C5pages/portfolio.html, assets/app.js (previous revision)A public page offered a text box for the Kalshi private key and signed requests with it in the page.Key handling moved to an opt-in, memory-only, acknowledgement-gated flow, and the recommended path is the local CLI (flag R1).
C6pages/suggestions.html (previous revision)Suggestion cards were rendered from a JavaScript string, so their text was not in the HTML and could not be reviewed or searched without running the script.Suggestions are now plain HTML with a small script that only attaches the decision buttons.
C7tools/ (previous revision)The link checker only inspected the verified/ subsite and only checked the five category pages, so a broken link anywhere else would not fail the build.The checker now walks the whole site and requires an official source link on every data row.
C8COORDINATION.mdTwo sessions appended to the file at the same time, which produced a merge conflict when this branch was rebased.The conflict was resolved by keeping both sides; the board now has one section per session (flag R5).
C9tools/collect_kalshi.pyThe first version matched single-word keywords with a plain substring test, so “eth” would have matched “something”.Single-word keywords now match on word boundaries; multi-word keywords match as substrings.
C10tools/kalshi_trade.pyThe first version detected the key type by looking for the word “RSA” in the openssl text output, which that output does not contain.The key type is now taken from the algorithm identifier in the SubjectPublicKeyInfo DER.
C11Repository rootA Python bytecode cache was committed by accident.Removed and ignored through .gitignore.

4 · Checks that run before publication

  • python3 tools/check_links.py — every internal link and anchor in the site resolves, and every data row on a category page carries a link to the Kalshi API response it came from.
  • python3 tools/test_signing.py — the request-signing implementation matches the official specification, verified offline against generated Ed25519 and RSA keys.
  • node --check on every script in assets/.
  • python3 tools/build_site.py regenerates the data-driven pages from data/, so a stale table cannot be published.
  • The Pages workflow fails the deployment if any of the above fails.

The run outputs are recorded in Verification and in COORDINATION.md.
