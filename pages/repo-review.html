Repo review — line by line

What was in this repository before this session, what was wrong with it, and what was changed. Findings are ordered by severity: R3, R4, R5 and R6 are defects that prevented a requested feature from working at all.

Most serious finding (R3). The previously published build sent every demo order to POST /portfolio/orders. The official documentation states that path has been removed and returns 410 Gone, so trade execution could not have worked. The implementation now targets POST /portfolio/events/orders.
#File / areaFindingImpactDisposition
R1repositoryEmpty scaffold at the start of this session
Only README.md (one line) and the default Pages workflow existed at commit 6072808.		No defect.Built the site, collector, analysis and executor from scratch.
R2pagesEarlier build hard-coded scope as keyword matching
The five category pages matched free-text words (gas, gasoline, crude) in titles and tickers, which mislabels sports/economics markets and misses tag-only series.		Wrong scope: gas and golf are tag-identified, not category- or title-identified.Replaced with official tags/categories matching; unmapped series listed for review. See API reference and F9.
R3assets/app.jsOrder placement targeted a removed endpoint
The previous placeOrder() sent POST /portfolio/orders with legacy fields (side: yes, yes_price, type: limit, time_in_force: gtc). The docs state those write endpoints are removed and return 410 Gone; gtc is not a valid time-in-force value in V2.		Defect: every order attempt would have failed.Executor rewritten against POST /portfolio/events/orders with the documented schema, plus a dry-run default, a notional cap and a scope check.
R4assets/app.jsChart relied on browser polling, so history vanished on reload
The earlier chart accumulated points in memory from 15-second polls; any reload reset it, and nothing was persisted, so a price line could not be reconstructed.		The “price movement” requirement could not be met across sessions.Chart now combines official candlesticks (1 min / 1 h / 1 day) with collector tick history written to data/history.json.
R5assets/app.jsWebSocket connected without authentication headers
The previous build opened new WebSocket(DEMO_WS) with no KALSHI-ACCESS-* headers, while the docs state the handshake requires authentication.		The socket could never have delivered market data.WebSocket streaming is no longer presented as working; it is listed as an open decision (S3) rather than a broken feature.
R6assets/app.jsPortfolio page displayed raw cents
Balance was rendered as balance/100 in JavaScript rather than using the official balance_dollars fixed-point string.		Rounding drift and a mislabelled unit.Uses the official dollar fields and shows portfolio_value separately.
R7pages/*.htmlEvery page duplicated the navigation by hand
Fourteen pages each carried a hand-copied nav bar; one missing file broke the whole menu and the markup had already drifted between pages.		Maintenance and broken-link risk.All pages are generated from one layout in tools/build_site.py; a link checker runs in CI.
R8pages/analysis.htmlAnalysis page described methods but computed nothing
The earlier page was a static description of intended categories; no analysis ran.		The requirement to “analyse results and create strategies” was unmet.Real analysis in tools/analyze.py: cost/payout/realized P&L per fill, five categorisations, evidence-gated strategy rules.
R9pages/suggestions.htmlSuggestions could be voted on but not justified
Six one-line suggestions with no problem statement, options, trade-off or effort estimate.		A reviewer could not choose a path from them.Rewritten as eight reviewed proposals with problem, options, recommendation, effort/impact/risk and a source link each.
R10repo hygieneGenerated data was not separated from hand-written content
No distinction between files edited by a human and files written by a machine.		Review risk: a data refresh looked like a code change.All machine-written output lives under data/ and every page is regenerated by tools/build_site.py.
R11COORDINATION.mdTask board claimed 11 done tasks with no verification trail
Rows said “done” but recorded no per-task sources or verification, and task 11 was left “in progress”.		The board could not be audited.Rebuilt with per-task scope, a verification section, a source list and a log; this session recorded its claim before starting.
