Flagged for review

Irregularities and unverified items, each with the source needed to check it by hand. None of them block the site. Review them after the site is live and ask for changes.

#ItemWhat was observedWhy it matters What was doneSource
F1Demo data is not real-market dataKalshi states demo prices and market behaviour “may not be reflective of those in real markets”. Demo series also carry 2099 close dates and synthetic strikes.Any result derived from demo prices does not transfer to live trading.Every page carries the demo warning; no live-trading claim is made anywhere.https://docs.kalshi.com/getting_started/demo_env
F2“Highest dollar amount” has no single API fieldKalshi defines notional_value_dollars as the value of one contract at settlement, so it is not turnover. volume_fp and open_interest_fp are contract counts.Any dollar ranking is a derived measure and can be argued with.The derived measure is labelled on every row and the ranking metric is a user choice.https://docs.kalshi.com/api-reference/market/get-markets
F3Topic scope is a hand-assembled allowlistThe allowlists use official tag and category strings from Kalshi's taxonomy endpoint, but the exact set per topic was chosen here.A market that Kalshi considers in-scope may be excluded, or vice versa.Publish the generated allowlist and review it (suggestion S1).https://docs.kalshi.com/api-reference/search/get-tags-for-series-categories
F4Only the top series per topic are collectedThe collector reads the highest-volume series per topic, because Get Series List returns volume_fp per series.A low-volume but relevant series may be missing from the snapshot.Raise --series-per-topic in the collector, or collect every in-scope series.https://docs.kalshi.com/api-reference/market/get-series-list
F5A browser page may not be able to call the demo APIPublic demo endpoints need no authentication, but browser CORS behaviour for this origin could not be confirmed from the build environment.Live prices and the order book may fail to load in some browsers.The site falls back to the verified snapshot and labels the state; a same-origin proxy is the fix (suggestion S3).https://docs.kalshi.com/getting_started/quick_start_market_data
F6The WebSocket feed is not usedKalshi requires the three authentication headers on the WebSocket handshake, and browsers cannot set custom headers on a WebSocket.Prices are a few seconds behind, and there are no order-book deltas.Use a relay (suggestion S3).https://docs.kalshi.com/getting_started/quick_start_websockets
F7No demo API credentials are held by this projectDemo keys are created by the account owner in the Kalshi demo UI and are signed per request.Portfolio performance, fills, settlements and executed trades cannot be reported until a key is loaded in the browser.Load a demo key on the Portfolio page, or provide a private backend (suggestion S2).https://docs.kalshi.com/getting_started/api_keys
F8Signed requests run from a public pageThe private key is kept in page memory only; it is never written to storage and is only used to sign.A public page is not an appropriate place for a long-lived credential.Move signing to a private backend (suggestion S2).https://docs.kalshi.com/getting_started/quick_start_authenticated_requests
F9Demo settlement sources contain placeholder textSeveral demo series list settlement sources with unfilled template text (for example “account holder of”) and some point at search-engine pages rather than a named source.The resolution rule for those contracts cannot be verified from the API alone.Read the contract terms PDF linked on each series before relying on a resolution.https://docs.kalshi.com/api-reference/market/get-series
F10Chart history is capped by the candlestick APIOne candlestick request may span at most 5,000 periods; 1-minute data therefore reaches about 3.5 days, and the dashboard offers windows up to 3 days.Longer-horizon analysis needs stored history.Store a rolling tape (suggestion S5).https://docs.kalshi.com/api-reference/market/get-market-candlesticks
F11Collection is limited by unauthenticated rate limitsUnauthenticated public requests have their own limits and return HTTP 429 without a Retry-After header.A harvest can be incomplete if the limit is hit repeatedly.The collector retries with exponential backoff and logs every request in data/collection-log.json.https://docs.kalshi.com/getting_started/rate_limits
F12Strategy and win-rate claims are not madeNo demo fills are available to this session, so there is no realised P&L, no win rate and no drawdown.The strategy table on the Analysis page is a hypothesis taxonomy, not a result.Load fills on the Portfolio page and the analysis becomes computable.https://docs.kalshi.com/api-reference/portfolio/get-fills
F13Three earlier partial implementations existed in the repositoryEarlier parallel sessions had produced pages/, verified/ and dashboard/ trees, each with its own navigation and data snapshot.Duplicate navigation and contradictory figures were possible.This integration keeps one site, one design system and one snapshot pipeline; the previous trees are removed and their content is folded in.https://github.com/karagemop466-tech/Demo2
