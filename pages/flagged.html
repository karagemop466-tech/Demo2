Flagged for review

Everything the build could not confirm from an official source is listed here with the links needed to check it. None of these items blocks the site, and none of them is silently presented as fact elsewhere on the site: unconfirmed values are shown as “—”.

1 · Items that could not be verified in this build

#ItemWhat is unverifiedWhy it mattersHow to review itSeverity
F1 Browser access to the demo API (CORS) The build sandbox cannot open a TLS connection to external-api.demo.kalshi.co from a shell, so it could not be confirmed whether a browser on a normal network may call the demo API directly. Decides whether the dashboard can refresh live in the visitor’s browser or must rely on the committed snapshot. Open the published dashboard and press Go live. The status line reports the exact error if it is blocked. Cross-check against Market Data, which shows browser fetch examples. high
F2 Meaning of notional_value_dollars The field is present on every market and is 1.0000 on ordinary binary demo markets, but the official reference does not describe what it represents. It is the only field in the market response whose name contains “notional”, so a reader may assume it is market notional. Search the official Get Markets schema and the glossary for a definition. Until then the site labels it as an unexplained API field and does not rank by it. medium
F3 Price convention for NO-side orders The V2 reference describes a “single-book bid/ask side” but does not restate, on the same page, which leg the price field is quoted in. The site converts NO prices as 1 − price and shows the conversion. If the convention differs, a NO order would rest at the wrong level. Place one resting (non-crossing) demo order and compare GET /portfolio/orders with GET /markets/{ticker}/orderbook. Sources: Order direction, Orderbook Responses. high
F4 Whether the signed WebSocket can be used from a static page The docs require signed headers for the handshake and do not state whether query-parameter or sub-protocol authentication is supported. Decides whether a seconds-granularity tick feed is possible without running a proxy. Check the WebSocket quick start and the WebSocket reference for an alternative authentication transport. medium
F5 Completeness of the topic universe The classifier uses official categories and tags plus title words. A market whose series has no matching tag and a title outside the word list is out of scope even if a human would call it in scope (for example a music or celebrity market with a neutral title). Determines whether a “culture” or “golf” market is missing from the dashboard. Compare the series.json catalogue in data/ with the series you expect, and adjust the rule list published on the Methodology page. Every row shows the rule that matched. medium
F6 Demo account track record No demo API credentials were available in the build environment, so no authenticated call could be executed or verified end-to-end, and no trade was placed by the build. The portfolio and analysis pages are implemented from the documented schema but have not been exercised against the live demo account. Create a demo key at demo.kalshi.co and load the Portfolio & trading page. Sources: Authenticated Requests, Create Order (V2). high
F7 Demo market data is synthetic Observed markets named “Demo BTC at or above …” with demo-only rules text, and multivariate events created minutes before the request. Any conclusion drawn from demo prices or outcomes is about the simulator, not about the real world. Read the demo-environment warning: Test In The Demo Environment. medium
F8 Status field vocabulary The documented status filter values are unopened, open, closed, settled, while live demo markets returned status: "active" and status: "finalized". Filters are applied as documented; the site does not branch on the field value, but a reader might expect them to match. Compare the filter documentation with the live payload: Get Markets. low
F9 Price-history coverage for old markets Markets that settled before Kalshi’s historical cutoff are not served by the live candlestick endpoint. The minute/hour graphs of long-settled markets would come back empty. Use GET /historical/markets/{ticker}/candlesticks — Historical Data. low
F10 Snapshot freshness The committed snapshot is only as fresh as the last successful CI run; the schedule is every 30 minutes. A reader may treat snapshot numbers as live. Every page shows the snapshot timestamp; the dashboard’s Go live button bypasses the snapshot. low
F11 “Trades executed on events” Trades are executed on the demo exchange only, by the visitor, using their own demo credentials. The build itself placed no trades and holds no account. The requirement to “execute trades” is satisfied by the implemented, verified-schema order entry, not by the build having traded. Place a demo order on the Portfolio & trading page; the request body and the raw response are shown on the page. high
F12 Historical strategy performance No historical fills exist for the demo account, so no strategy can be stated from data yet; the analysis page states this explicitly rather than inventing a rule. Without fills, the “categorise trades and create strategies” requirement is implemented but not yet populated. Place several demo orders across at least three price bands or topics, let them settle, and revisit Trade analysis. medium

2 · Observed but unexplained

#ObservationWhere it came fromWhat is still unknownHow to review
O1The demo API returns markets from many official categories (Elections, Entertainment, Sports, Financials, Mentions, World …) with live-looking prices, plus explicitly synthetic “Demo …” markets. Live calls L1–L4 Which of those markets a demo account can actually trade and settle. Try one per category on the Portfolio & trading page and read the exchange’s error codes — Order Errors.
O2Volume figures on demo markets are frequently round numbers (for example 150.00 contracts per 1-minute candle). Live candle response L5 Whether volume is simulated rather than generated by actual trades. Compare several markets’ candle volume series; Kalshi does not document demo data generation.
O3The order-book endpoint returns 200 with empty arrays for a ticker that does not exist, rather than 404. Orderbook Responses (“Empty and Unknown Markets”) Nothing — this is documented behaviour. The site therefore validates a ticker with GET /markets/{ticker} before showing an order book.

3 · How to propose a change

Anything that would close one of these items belongs on the Suggestions board with its evidence, so the change can be accepted before it is made. Questions that need an answer first are listed on the Questions page.
