Executive summary

A source-linked dashboard for five Kalshi demo topics

A live dashboard over the Kalshi demo Trade API, limited to gas prices, elections, culture, crypto and golf. Every market row links back to the exact official API response it was read from; no value is inferred, and any field the API does not return is left blank and marked unverified.

1 · The data behind this site

Figures come from the committed snapshot, refreshed automatically by the scheduled collector. The full request log is in data/collection_log.json.

3 · How the data flows

  • Collector — tools/collect_kalshi.py calls the public demo endpoints (/markets, /events, /series, /markets/{t}/orderbook), follows the cursor to the end of each listing, classifies every market against the official category and tag taxonomy, and writes data/*.json. No authentication is used, so no secret ever enters the repository.
  • Scheduler — .github/workflows/collect.yml runs the collector on a GitHub-hosted runner (the build sandbox has no outbound route to the Kalshi hosts) and commits the result.
  • Pages — tools/build_site.py regenerates the category and verification pages from data/, so a published table can never disagree with the committed snapshot.
  • Browser — assets/app.js tries the live API first. If the request fails (network or CORS) it switches to the committed snapshot and says so in the status line, rather than showing a stale value as if it were live.
  • Checks — tools/check_links.py fails the build on a broken link or a data row without an official source link; tools/test_signing.py fails if the request signature stops matching the published specification.

5 · Limits, and the one hard blocker

There is no Kalshi account, so there are no account numbers. Portfolio balance, positions, fills, settlements, executed trades and every performance statistic are blank on this site, and no trade was executed. A demo account can only be created by a person at demo.kalshi.co/sign-up because it needs an email address and a password. The trading, categorisation and analysis code is finished and its signing is verified, so connecting a key fills the tables automatically. This is question Q1.
  • Demo prices are not real prices. Kalshi states demo behaviour may not reflect real markets, and the demo environment contains synthetic contracts.
  • No fee-aware figures. The Kalshi fee schedule has not been read in this session, so every P&L figure is gross and labelled as such (question Q2).
  • Browser access is unverified. If the published page cannot call the demo API directly, it says “Snapshot mode” and serves the committed snapshot instead; the freshness then depends on the scheduled collector.
  • Second-level ticks depend on polling. The WebSocket feed is not used for data; the chart combines official candles with REST polling.
  • Nothing here is trading advice, and the strategy categories on the Analysis page are labelling rules, not validated systems.
