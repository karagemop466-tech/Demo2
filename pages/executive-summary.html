Executive summary

A dashboard that collects, organises and analyses Kalshi demo markets in five topics only - gas prices, elections, culture, crypto, golf - tracks them until they resolve yes/no, charts price against time with selectable windows, shows contracts available at each price, and reports demo-account performance with trade categorisation and strategy candidates.

What was asked, and where it lives

  • Highest dollar-amount live events, five topics only - Dashboard ranks by a labelled estimate; the raw official fields sit beside it. Scope is decided by official series tags/categories, not by keyword guessing.
  • Track until resolved, yes or no - Resolutions lists every settled in-scope market with Kalshi’s own result field.
  • Portfolio performance on the demo account - Portfolio.
  • Analyse results, categorise trades, build strategies - Analysis. Strategies are only emitted above an evidence threshold, otherwise the page says “insufficient data” rather than inventing a rule.
  • Execute trades and track performance - signed demo orders via POST /portfolio/events/orders; every attempt is logged with its HTTP status.
  • Live interactive graph, X = time, Y = contract price, seconds to days - Dashboard chart, 60 s / 5 m / 1 h / 6 h / 24 h / 7 d.
  • Current liquidity: how many contracts at a given price - order-book panel on the Dashboard; full depth on each category page.
  • Suggestions section to choose a path before implementing - Suggestions (decisions are recorded, nothing auto-applies).
  • Questions / information / answers needed before deciding - Questions.

How the data is actually obtained

This is a static GitHub Pages site, so it cannot hold a secret and a visitor’s browser cannot be the only data path. Instead:

  1. A GitHub Actions workflow runs tools/collector.py every 10 minutes against the official demo API (demo environment).
  2. The collector writes data/*.json, including an API log of every request and its HTTP status, and commits the snapshot.
  3. The pages read those snapshots, so every number on screen traces back to a logged request.

Consequence stated plainly: the committed snapshot is refreshed by a scheduled job, and GitHub may delay scheduled runs (observed gaps of hours; F24). Since 2026-11-21 the dashboard therefore also polls the public order-book and market endpoints every 30 seconds while the tab is visible and plots that live point beside the collected history. The snapshot remains the audit trail and each series is labelled by source. This needs no key and no WebSocket handshake; the documented WebSocket channel requires authentication, which a public page must not hold (F14).

What it explicitly does not do

  • No real-money trading. Demo host only, hard-coded.
  • No invented values: missing data renders as an em dash and the row is marked unverified.
  • No strategy claim below the evidence threshold.
  • No claim that demo prices predict production prices - Kalshi’s own docs warn they may not be reflective (demo_env).

Headline risks

  • Definition risk. “Highest dollar amount” has no single API field; the ranking is an estimate (F2, Q1).
  • Coverage risk. Demo liquidity is thin and some demo series carry placeholder strikes; sample sizes for strategy work will be small for a long time (F8).
  • Credentials. Portfolio and execution need a demo API key pair configured as repository secrets. Until then those pages show an explicit “not configured” state, not zeros.
  • Correctness defect found and fixed. The earlier build posted orders to a removed endpoint; it is documented in F7.

Bottom line

Built and sourced: the five-topic scope, the ranked live view, the time-versus-price chart, order-book depth, yes/no resolution tracking, trade categorisation, a strategy engine that refuses to guess, a review gate for suggestions, and a price-jump page for moves of $0.10 or more between official trade prints (Price Jumps, added in this review).

Not done, and why. Demo-account portfolio tracking and order execution need a Kalshi demo API key, and this workspace has none (F19). Culture has no open markets in the collected data (F20). The gas topic includes solar, electricity and refinery markets (F14). The jump page cannot name a cause, because no official source links a price move to news (F18), and snapshots are too coarse for intraday moves (F17). A public page takes a demo private key as input (F21). The live alert chats (Live Alerts) now run in the browser against the demo API and the simulated strategy lab runs without keys, but the high-ROI filter is a labelled local heuristic (F22) and the simulation does not model fees or slippage (F23).

What remains open is definition and access: what “highest dollar amount” means, how fresh the data must be, whether a demo key will be supplied, and how much evidence is enough before a strategy is trusted. Those are listed, with the exact information needed to close them, on Questions.
