Suggestions — review board

Every proposal below is recorded with the evidence behind it and a link to the official Kalshi documentation that supports it. Nothing here has been implemented. The board exists so a reviewer can accept, defer or reject each item before any change is made. Decisions are stored in this browser only (localStorage) and can be printed or copied.

S1Live feed Add a signed WebSocket feed for the ticker channel instead of 3-second REST polling. The WebSocket handshake requires signed headers, and a browser WebSocket cannot set custom headers — Quick Start: WebSockets. Fix: a 20-line signed proxy, or keep REST polling. Lower latency and far fewer REST calls; seconds-scale graphs become tick-accurate. Medium A proxy holds a signing key — it must never be a public, unauthenticated service. pending
S2Charts Persist candle history in the CI snapshot so a multi-day graph survives a page reload and works offline. The official endpoint already returns OHLC history — Get Market Candlesticks (1 / 60 / 1440-minute periods, max 5,000 periods per request). Removes the “history is this browser session only” limitation. Low Larger repository; snapshot size must be capped. pending
S3Order book Add a “spread and depth within N cents” column to the ranking table, computed from live order books. Orderbook Responses defines best bid, implied ask, spread and depth; the REST endpoint supports a depth parameter. Turns the ranking into an executability measure, not just a size measure. Medium One order-book request per market is expensive; needs a short list or sampling. pending
S4Resolution Add a “resolves next” calendar built from close_time / expected_expiration_time. Both fields are on the official market response — Get Markets — and settlement timing is described in Market Settlement. Makes “track until resolved” actionable rather than passive. Low Close times shift, so the view must always re-read the API. pending
S5Costs Show the fee schedule (fee_type, fee_multiplier) for each series before a trade is placed. Both fields are on the official series record — Get Series List; rounding is described in Fixed-Point Representation. Turns “is this price good?” into “is this price good after fees?”. Low Fee schedules change; always read them live. pending
S6Analysis Add a strategy lab that back-tests a rule over the snapshot’s settled markets (not over the user’s fills). The snapshot already carries settled markets with their official result — Get Markets. Shows what a rule would have done before risking anything. Medium Overfitting to demo data; results must be labelled as demo-only. pending
S7Reliability Add a CI data-quality gate: fail the build if the snapshot contains zero in-scope markets, or if the fetch reports errors. GET /exchange/status exposes exchange_active and trading_active — Get Exchange Status. Prevents a silent classifier regression from publishing an empty site. Low A strict gate could block the site during a demo outage. pending
S8Operations Show the account’s API usage tier and remaining budget next to the trade ticket. GET /account/api/limits is documented — Get Account API Limits — and rate limits are described in Rate Limits and Tiers. Prevents accidental throttling during polling. Low None material. pending
S9Execution Show queue position for resting orders so the user can judge whether an order is likely to fill. GET /portfolio/orders/queue_positions is documented — Get Queue Positions for Orders. Improves order placement decisions. Low Queue position is informational only. pending
S10Research Decide on one external probability source per topic and add an “implied probability vs external estimate” panel. No Kalshi endpoint publishes an outside probability estimate, so a source must be chosen and cited — see the open items on the Questions page. Turns the dashboard from a monitor into an edge-detection tool. High Licensing, staleness and false-precision risk; the panel must show the source and timestamp. pending
S11Portability Add a one-click switch between the two documented demo hosts to compare behaviour. Both hosts are officially supported: external-api.demo.kalshi.co (recommended) and demo-api.kalshi.co — API Environments and Endpoints. Useful if one host is degraded or geo-restricted for the user. Low None material. pending
S12Usability Add a “paper mode” that replays the snapshot to simulate fills so strategy ideas can be tested without an API key. Simulation only — it must be labelled as not a real fill. Order semantics come from Create Order (V2). Lets a reviewer explore without credentials. Medium Simulated results must never be mixed with real fill data in the analysis page. pending
S13Scheduling Move the CI refresh to a shorter interval for the in-scope subset only, and publish the age of the data on every page. Each dataset already records generated_at; the schedule lives in .github/workflows/refresh-data.yml. Keeps the “live” claim honest for the topics that matter. Low More CI minutes; GitHub Actions quotas apply. pending

How a decision is recorded

Each row can be marked accept, defer or reject with a short note. A rejected item stays on the register with its reason, so the reasoning survives. Because the site is static, decisions live in this browser; to make them permanent, copy the notes into the repository’s COORDINATION.md.
