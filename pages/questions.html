Questions, information and answers needed before deciding

Twelve questions stand between the current build and a decision that is defensible. For each one: what we already know from an official source, exactly what is still missing, how it can be discovered, and the source that anchors the known part. Nothing here is padded with questions that the data already answers.

Already answered by verified sources (so not listed as open): the demo REST/WS base URLs; that public market data needs no authentication; the signing algorithm and pre-sign string; that the legacy order endpoint returns 410; that the order book has no ask side; that candles cap at 5,000 periods; that gas and golf are tag-identified rather than category-identified. See API reference.

The single question that blocks the most

Q1, the definition of “highest dollar amount”. Every ranking on every page inherits it. It is a one-line policy decision, but until it is made the dashboard must present three sort keys side by side and label its own ranking an estimate. If a dollar-volume figure is required exactly, it has to be reconstructed from individual trades (GET /markets/trades: price × contracts summed per market), which is a materially larger collection job and a separate decision.

What would change if Q3 (freshness) were answered “live only”

The static-site architecture would need a relay. That is a hosting, secret-management and cost decision, not a coding one. The current design deliberately keeps everything inside GitHub so there is nothing to pay for and nothing to leak.
