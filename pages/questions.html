Questions, information and answers needed

Everything below is either answered from an official source, or explicitly left open with the missing information named and a way to obtain it. No answer is invented.

#QuestionWhat we know (verified)What is missing How to obtain itSource
Q1What exactly does “highest dollar amount” mean?Get Markets returns volume_fp (contracts), open_interest_fp (contracts), last_price_dollars ($/contract) and notional_value_dollars, which Kalshi defines as the value of a single contract at settlement.There is no dollar-turnover field. The dashboard ranks on contracts × last price and labels it as derived; open-interest value is offered as an alternative.Choose one measure and make it the default; both are already available as options in the dashboard ranking selector.https://docs.kalshi.com/api-reference/market/get-markets
Q2Which markets belong to each of the five topics?Kalshi publishes a category → tag taxonomy, and every series carries a category and tags.The allowlists are hand-assembled from official tag strings; a series whose topic is only implied by its title is excluded.Generate the allowlist from the taxonomy in the collector and publish it as a reviewable file (suggestion S1).https://docs.kalshi.com/api-reference/search/get-tags-for-series-categories
Q3Which demo account and API key will be used?Demo keys are created in the Kalshi demo UI and are signed per request; no demo credentials exist in this repository.Without a key there is no balance, no positions, no fills and no executed trades, so portfolio performance cannot be reported yet.Create a demo key at demo.kalshi.co and load it in the browser on the Portfolio page, or provide a private backend (suggestion S2).https://docs.kalshi.com/getting_started/api_keys
Q4How long should a market be tracked after it settles?Get Markets returns settled markets with result, settlement_value_dollars and settlement_ts.The snapshot keeps the settled rows collected for each topic; there is no long-term archive.Decide a retention window and store a settlement ledger per event.https://docs.kalshi.com/api-reference/market/get-markets
Q5What price history should the chart use?Kalshi publishes candlesticks with 1, 60 and 1440 minute periods, limited to 5,000 periods per request.The chart therefore shows at most three days at daily resolution; a longer window needs a stored tape.Choose the maximum look-back and store it (suggestion S5).https://docs.kalshi.com/api-reference/market/get-market-candlesticks
Q6Is browser polling fast enough for decisions?REST market data is cached briefly and can lag the exchange by several seconds; Kalshi points to WebSockets for current prices.The dashboard polls, so it is a few seconds behind and never receives order-book deltas.Set a latency target and, if it matters, run the WebSocket bridge (suggestion S3).https://docs.kalshi.com/getting_started/quick_start_market_data
Q7Which liquidity measure should be shown?The order book returns resting YES and NO bids as [price, contracts] arrays; asks are the reciprocal of the other side's bids.Only bids are available; there is no separate ask ladder and no aggregated depth endpoint.Decide whether to show the reciprocal ask side, and at what depth.https://docs.kalshi.com/api-reference/market/get-market-orderbook
Q8How should fees and net P&L be computed?Kalshi documents fee rounding and per-series fee structures (quadratic, with optional maker rebates).No fee is charged in the snapshot; net P&L can only be computed from real fills.Confirm the fee inputs once fills exist and define the P&L formula (suggestion S6).https://docs.kalshi.com/getting_started/fee_rounding
Q9Is it acceptable to run signed requests from a public page?The signing scheme is documented and the key never leaves the page in this implementation.A public page is still the wrong place for a private key. No key is stored, but the exposure is non-zero.Move signing to a private backend (suggestion S2).https://docs.kalshi.com/getting_started/quick_start_authenticated_requests
Q10Should demo results be used to judge a strategy?Kalshi warns that demo prices and behaviour may not reflect real markets.Demo P&L cannot validate a strategy for live trading.Agree up front that demo results are a pipeline test only, and require out-of-sample validation before any live use.https://docs.kalshi.com/getting_started/demo_env
Q11Which demo account, key and subaccount will be used?Portfolio balance, positions, fills and orders all require a signed demo key. No credential is held by this repository.Until a key is loaded in the browser, portfolio performance and executed trades cannot be reported — every portfolio figure on the site stays blank rather than invented.Create a demo key at demo.kalshi.co, load it in the browser on the Portfolio page, or provide a private backend (suggestion S2).https://docs.kalshi.com/getting_started/api_keys
Q12Will the browser be able to reach the Kalshi demo API from the published site?Public demo endpoints need no authentication, so no credential blocks the request. Whether the demo host sends permissive CORS headers for the GitHub Pages origin was not confirmed from the build environment.If the browser is blocked, live prices and the order book will not load in the reader's browser; the page falls back to the committed snapshot.Confirm in a browser from the deployed URL and, if blocked, add a same-origin proxy (suggestion S3).https://docs.kalshi.com/getting_started/quick_start_market_data
Q13Should third-party gas-price and “record” figures be quoted anywhere?National-average gas prices and record claims appear in third-party articles. Kalshi publishes no equivalent authoritative series.A third-party figure is not an official source, so quoting it would break the rule that every value comes from an official source.They are not used anywhere on this site. If they are wanted later, state the publisher and link on every row.https://docs.kalshi.com/getting_started/demo_env
Q14Should the Kalshi fee schedule be opened and quoted?The API documentation links a fee schedule PDF. It was not opened during this build.Fees affect net P&L and the strategy table, so the exact schedule matters once fills exist.Open the fee schedule PDF and record the per-series fee inputs on the Analysis page.https://docs.kalshi.com/getting_started/fee_rounding
Q15How complete is the collected catalogue?The collector reads a bounded number of series per topic and paginates the API; earlier collection runs were truncated by rate limits.The snapshot is a sample of the catalogue, not the whole catalogue. Coverage is a percentage of what exists, not everything.Publish the generated allowlist with the collection log (suggestion S1) and record the coverage per topic.https://docs.kalshi.com/getting_started/pagination
Q16Should production (real-money) markets be included?Kalshi runs a separate production environment. Every figure published here comes from the demo environment.Demo values are mock values. Mixing environments without labelling would produce misleading comparisons.Keep the site on demo and label every figure; only extend to production behind a separate, clearly marked deployment.https://docs.kalshi.com/getting_started/api_environments

Questions that only the account owner can answer

  • Which demo API key will be connected, and who owns it?
  • What is the maximum number of contracts a single demo order may place?
  • Should orders be placed automatically, or only after an explicit per-order confirmation?
  • Which categories may be traded at all, and which are observation-only?
  • What is the stopping rule if the demo account loses a set fraction of its mock funds?

These are policy decisions, not technical unknowns; they are not filled in on your behalf.
