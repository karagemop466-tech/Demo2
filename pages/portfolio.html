Portfolio & Trading

Account connection is intentionally disabled

This site is a static GitHub Pages application. It has no trusted server to protect signing credentials. Do not paste an API key or private key into this site. A browser-side key-entry/trading flow would expose a powerful secret to site scripts and any compromise of the hosting origin.

Portfolio values, positions, fills, and trade performance are therefore blank—not estimated—and order submission is not available. No account data is fabricated.

To enable this safely, review the proposal on Suggestions: build a separately hosted backend that stores credentials in a secret manager, authenticates the account owner, limits demo access, validates orders, and logs activity. Until then, use Kalshi's official demo interface directly.

Trade analysis & strategy framework (runs locally)

When you have a demo key, the bundled CLI categorises every trade and computes performance without the key ever touching this site:

StepCommand / methodWhat it produces
Track portfoliopython3 tools/kalshi_trade.py balance · positions · fillsBalance, positions and fills from your demo account (authenticated endpoints per Authenticated Requests)
Execute tradespython3 tools/kalshi_trade.py order --ticker … --side yes|no --count … --price …Places a demo limit order (signing per API Keys: Ed25519 or RSA-PSS/SHA-256, timestamp+method+path)
Analyze & categorizepython3 tools/kalshi_trade.py reportTrades grouped by topic (gas prices, elections, culture, crypto, golf, other), side, and settled outcome (win/loss joined to the official result); net P&L from settlement value − entry price
StrategiesReport output, ≥5 fills per categoryStrategy candidates per trade type; “insufficient data” otherwise. Nothing is recommended without observed fills.

Signing self-test (offline): python3 tools/kalshi_trade.py selftest — Ed25519 and RSA-PSS verified locally, no network calls. Set KALSHI_KEY_ID and KALSHI_PRIVATE_KEY_FILE in your shell; never commit keys.
