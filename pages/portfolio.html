Portfolio & trading (demo account)

Everything on this page runs in your browser and talks directly to the Kalshi demo API. Your private key is used only to sign requests — it is held in sessionStorage (cleared when the tab closes), is never uploaded, and is never stored in this repository. Demo money has no value.

How to get demo credentials. Create a free account at demo.kalshi.co → Account & security → API Keys → Create Key. You get an API Key ID and a private key (PEM). Demo keys only work against the demo hosts — API Environments.

1 · Credentials

Signing follows the official scheme: timestamp + METHOD + path, RSA-PSS with SHA-256 or Ed25519, base64 signature in KALSHI-ACCESS-SIGNATURE, millisecond timestamp, 30-second tolerance — Authenticated Requests. The signed path never includes the query string.

2 · Portfolio

Enter credentials above and press Load portfolio.

3 · Place a demo order

Buys YES at the price you enter (side = bid).

Uses POST /portfolio/events/orders — Create Order (V2)

How this maps to the official V2 request

Create Order (V2) uses a single book with a bid/ask side and fixed-point dollar prices. Order direction maps bid ≡ yes and ask ≡ no, and Orderbook Responses shows that a YES bid at $X is a NO ask at $(1 − X).

Prices are snapped to the market's own price_ranges grid, which the official fixed-point guide names as the source of truth for valid prices — Fixed-Point Representation. An off-grid price is rejected by the exchange with invalid_price.

4 · What happens to the trade record

Every order you place is written to this browser's local trade log, and every fill returned by GET /portfolio/fills is categorised on the Trade analysis page (topic, outcome side, price band, hour of day, taker/maker) with results computed only from markets that have actually settled. Strategies are never asserted unless the fills support them.
