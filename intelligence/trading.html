Trading — demo order execution

Build a Create Order (V2) request against the official spec, export it as a ready-to-run signed call, and submit it through a secured path (local backend with environment-variable keys, or Kalshi's official docs playground). This static page never accepts private keys.

Security decision (F-17, decision D-05): no credentials in the browser. Repository policy on main states plainly: “Do not place private signing keys in a public static site… Do not enter credentials in a public GitHub Pages application” — see the repo README and open PR #6 “Disable unsafe browser-side trading credentials”. An earlier draft of this page offered key paste + client-side signing; post-integration review removed it. The signing spec itself is still documented below (it is public knowledge from official docs) — only the credential-entry vector was removed.

Order ticket — builds the official V2 request body

Fields are validated against the Create Order (V2) spec: required ticker, side ∈ bid|ask, count, price, time_in_force, self_trade_prevention_type. Source: docs · Create Order (V2).

Request (verbatim JSON)
 
{ "ticker": "…", "side": "bid", "count": "10.00", "price": "0.5600", "time_in_force": "good_till_canceled", "self_trade_prevention_type": "taker_at_cross" }
Signed curl export (env placeholders — fill locally, never paste keys here)
 
Press “Build request body”.

Signature recipe (official): message = timestamp_ms + "POST" + "/trade-api/v2/portfolio/events/orders" (path without query) → RSA-PSS SHA-256 (salt = digest length) or Ed25519 → base64 → headers KALSHI-ACCESS-KEY, KALSHI-ACCESS-TIMESTAMP, KALSHI-ACCESS-SIGNATURE; ±30 s clock tolerance — authenticated-requests quickstart.

Account activity (balance · positions · fills)

Unavailable from a static page by design. GET /portfolio/balance, /portfolio/positions and /portfolio/fills require signed requests (official spec), and signing keys must not enter a public web page (F-17 / repo policy). Use path 1 (local backend) to view account data; this site's Portfolio & Analysis page shows the verified metrics formulas and the public-feed trade-analysis engine, with personal tables left blank until a secured source exists.
