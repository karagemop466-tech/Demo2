Portfolio & trades

This page will show balance, positions, executed trades and per-trade P&L for a Kalshi demo account — once one exists. It shows no numbers today because there is no demo account and no API key in this project, and inventing sample figures would be worse than showing none.

Why there is no data here

Portfolio endpoints require a signed request: an API key ID plus a private key, with each call signed over timestamp + method + path (authenticated requests, API keys). A private key cannot be shipped to a browser: anything in this public site is delivered to every visitor. So the honest options are a server-side signer (recommended) or no portfolio page at all. Both are laid out on Suggestion S1, and the blocking questions are Q16 and Q17.

Trade execution

Not available on this site, by design

Order placement needs the same signed requests as the portfolio. The previous implementation asked you to paste a private key into the page; that code is removed from the new site and flagged (F-08). To enable execution, choose an option on S1 first — the recommendation is a GitHub Actions job holding the key as an encrypted repository secret, which keeps the site read-only and leaves the order history in the commit log.

What performance analysis will look like

Once fills exist, this page will report, per category: number of trades, win rate, average entry price, total fees, realised P&L and average holding time — each recomputable from the fill records and each carrying its source. Until then, the only analysis that can be defended is market-level calibration, which is on the Analysis page.
