A. Scope — which contracts belong in gas, elections, culture, crypto and golf

Q1 · Where does Kalshi assign the topic of a market — on the series, the event or the market? ANSWERED
On the series. Get Series List returns a single primary category, a discovery list categories, and a tags array. Events carry a deprecated category field. The docs tell you to use the series-level category.
Why it matters
Topic membership is decided by series discovery queries, not by matching words in market titles.
How to find out
Already done: the collector queries series by category and by tag and records the exact query for every topic (see Verification page).
Sources
  • Get Series List (category / categories / tags fields)
  • Get Events (category marked deprecated)
Q2 · Is there a Kalshi category literally called Culture, and how large is it? ANSWERED
/series?category=Culture returns exactly 2 series in the demo API: KXXBANNEDGROK (“Will Grok be banned this year”) and KXXBANNEDMURRAYHILLGUY1 (“Will @MurrayHillGuy1 get banned from X this year?”). “Culture” is not listed as a category in search/tags_by_categories, whose categories are AI, Business, Climate and Weather, Commodities, Companies, Crypto, Economics, Elections, Entertainment, Financials, Health, Mentions, Politics, Science and Technology, Social, Sports, Test, World, harrison-test.
Why it matters
A pure “Culture” filter produces a two-row dashboard. Entertainment (music, awards, TV, movies, video games) is where most culture contracts actually sit.
How to find out
Done. The Culture page shows the two true Culture series and a separately labelled Entertainment table, so nothing is silently reclassified.
Sources
  • API response: series?category=Culture
  • API response: search/tags_by_categories
Q3 · Is Golf its own category? ANSWERED
No. Golf appears only as a tag inside the Sports category in search/tags_by_categories. The collector therefore uses /series?tags=Golf.
Why it matters
Golf must be queried by tag; a category query would return nothing.
How to find out
Done.
Sources
  • API response: search/tags_by_categories (Sports → Golf)
  • Get Series List (tags parameter)
Q4 · Which gas-price contracts exist, and are they city, state or national? ANSWERED
The demo API returns daily AAA state-level series (for example Oklahoma KXAAAGASCDOK and Tennessee KXAAAGASDTN), both tagged Oil and energy, both with settlement source AAA. Contract terms are at assets.kalshi.com/contract_terms/AAAGAS*.pdf.
Why it matters
Gas rows are state averages published by AAA, not national retail averages, and they settle daily.
How to find out
Done; the full series list is rendered on the Gas page with each contract's terms link.
Sources
  • API response: series?category=Economics
  • Get Series (settlement_sources field)
Q5 · Does “highest dollar amount” mean dollar turnover, notional, or open interest in dollars? PARTIAL
Kalshi publishes no single dollar-turnover field. The market object exposes volume_fp (contracts), volume_24h_fp (contracts), open_interest_fp (contracts) and last_price_dollars. Dollar figures are therefore computed as contracts × last price and are labelled as such everywhere.
Still missing
Which of the three is the ranking the business actually wants. Also unconfirmed: whether Kalshi sells a historical aggregate-volume product that would give true dollar turnover.
Why it matters
The dashboard ranks by open-interest dollars by default and shows all three measures in every table, so a reviewer can re-sort without a rebuild.
How to find out
Decide the metric (Suggestion S2). If true dollar turnover is required, request historical trades via /markets/trades and aggregate count_fp × yes_price_dollars — that is a query cost decision, not an unknown.
Sources
  • Get Markets (volume_fp, open_interest_fp, last_price_dollars)
  • Fixed-point representation
Q6 · Are there in-scope markets whose series metadata is missing, so they cannot be classified? PARTIAL
The collector records every series it saw and flags any with no settlement source. Markets whose series is not in the collected set are never shown as in-scope.
Still missing
A market could exist under a series outside our five discovery queries and therefore be silently out of scope. This is bounded by construction but not provably complete.
Why it matters
Scope completeness is a known limitation, not a data error.
How to find out
Routine audit: list all series with /series?limit=200 across the 19 categories and diff against the collector's scope queries. Cheap to automate; listed as Suggestion S8.
Sources
  • Get Series List

B. Live tracking and resolution

Q7 · How is a market's outcome recorded, and is it authoritative? ANSWERED
The Market object has a result field with enum yes, no, scalar or empty. Settlement pays $1 per contract to the winning side. The collector copies result verbatim from settled-market responses and never derives it.
Why it matters
Resolution tracking is a direct read of an official field, including the timestamped response URL for each row.
How to find out
Done.
Sources
  • Get Markets (result enum)
  • Market settlement ($1 per winning contract)
Q8 · How long do settled markets stay in the live endpoint? PARTIAL
Kalshi partitions data: markets that settled before the market_settled_ts cutoff are only available through GET /historical/markets. The cutoff is published by GET /historical/cutoff.
Still missing
The current cutoff value for the demo environment was not read in this pass, so the collector cannot say whether any given settled row is near archival.
Why it matters
Historical rows may disappear from the live endpoint. The dashboard stores every resolved row it has ever seen in data/history so a resolution is not lost when a market is archived.
How to find out
Suggestion S9: add GET /historical/cutoff to the collector and display the three cutoffs on the Verification page.
Sources
  • Historical Data (cutoffs and archival)
Q9 · Does the demo exchange trade, or is it a mock? ANSWERED
GET /exchange/status returned exchange_active: true and trading_active: true for four exchange indices at collection time. Real order flow exists; the money is mock.
Why it matters
Prices move because other demo participants trade, but Kalshi warns demo prices may not reflect real markets.
How to find out
Done; the collection time and result are shown on the Overview and Verification pages.
Sources
  • API response: exchange/status
  • Demo environment caveat
Q10 · Why do some demo markets carry a 2099 close date or a 'demo strike'? PARTIAL
Observed in the demo data: events such as KXNEXTNATOSECGEN-99 and KXELONMARS-99 carry close_time in 2099, and some markets carry custom_strike reading “demo strike”. Kalshi's demo page states prices and behaviour may not reflect real markets but does not document these placeholders.
Still missing
Kalshi's own explanation of what these placeholder strikes mean for settlement.
Why it matters
These rows are displayed as returned and flagged; they are never treated as a real-market signal.
How to find out
Ask Kalshi support, or compare the same series on the production API in a read-only call, to see whether the placeholder is demo-only.
Sources
  • Demo environment caveat
  • API response: events?status=open

C. Liquidity and price history

Q11 · Does the orderbook give asks, and how do I read 'how many contracts are available at a price'? ANSWERED
No asks are returned. The book lists YES bids and NO bids as [price, count] levels, ascending, best bid last. A YES bid at X is equivalent to a NO ask at 1−X, and a NO bid at Y is a YES ask at 1−Y. Counts are contracts, not dollars.
Why it matters
Availability at a price is answered by reading the level arrays directly and by the implied ask, both computed by plain arithmetic from the returned levels.
How to find out
Done; the Live page renders every level with a depth bar and shows cumulated contracts.
Sources
  • Orderbook Responses
Q12 · Can I draw a price chart with seconds/minutes/hours windows from the API alone? PARTIAL
Candlesticks exist at 1-minute, 1-hour and 1-day intervals only — there is no seconds interval. A seconds-granularity chart is only possible by polling the market or orderbook endpoint and storing each tick; the REST cache holds prices for about one second, and the docs recommend the WebSocket for current state.
Still missing
WebSocket price streaming from a static GitHub Pages origin has not been verified end to end.
Why it matters
The chart offers 60 seconds / 5 minutes / 15 minutes / 1 hour / 6 hours. Second-level points come from live polling in the visitor's browser plus the collector's 15-minute snapshots; minute and hour points come from the official candlestick endpoint. The two sources are labelled separately on the chart.
How to find out
Suggestion S4: verify the WebSocket API in a browser from the Pages origin and, if it works, add a streaming toggle; until then the chart is explicitly poll-based.
Sources
  • Get Market Candlesticks (1/60/1440 minutes only)
  • Get Markets (responses cached, can lag seconds)
  • WebSocket quick start
Q13 · What is the price-history retention limit? ANSWERED
One candlestick request may span at most 5,000 periods; 1-minute candles are therefore limited to about 3.5 days per request. Markets settled before the historical cutoff need the /historical/markets variant.
Why it matters
Any multi-week minute-level chart must be assembled from several requests.
How to find out
Done; the collector and chart stay inside these limits.
Sources
  • Get Market Candlesticks (5,000 period limit)
Q14 · What are the rate limits, and do they permit a browser-left-open dashboard? PARTIAL
Authenticated calls are token-metered by tier. Unauthenticated public calls are subject to separate limits that Kalshi explicitly does not publish. Responses expose X-RateLimit-* headers only for metered buckets.
Still missing
The numeric unauthenticated limit for the demo host.
Why it matters
The dashboard polls conservatively (one market plus one orderbook per refresh, default 15 s) and backs off on HTTP 429, but the safe ceiling is unknown.
How to find out
Read the X-RateLimit headers returned on a burst of public calls and record the tightest observed value; or ask Kalshi. Logged as flag F-11.
Sources
  • Rate Limits and Tiers

D. Portfolio, trades and strategy

Q15 · What exactly is needed to read a portfolio or place an order? ANSWERED
An API key ID and a private key (RSA-PSS/SHA-256 or Ed25519). Each request is signed over timestamp + method + path using a millisecond timestamp, and the signature is sent in KALSHI-ACCESS-SIGNATURE alongside KALSHI-ACCESS-KEY and KALSHI-ACCESS-TIMESTAMP. Credentials are separate between demo and production.
Why it matters
Portfolio and trading are impossible without account credentials. They cannot be included in a public static site.
How to find out
Done — see the decision below (D1 on Suggestions).
Sources
  • API Keys
  • Authenticated requests
  • Create your first order
Q16 · Can the demo account be created, and trades placed, without a human login? BLOCKED
No. Creating a demo account requires a Kalshi sign-up and login in a browser; API keys are generated from that logged-in account. No automated path exists and no credentials exist in this repository — by design.
Still missing
The account itself, and the API key ID + private key that only Kalshi's dashboard can issue.
Why it matters
Until a key exists, portfolio metrics, order execution and per-trade performance are unavailable, and the dashboard says so rather than showing zeros or sample numbers.
How to find out
Either (a) a human creates the demo account and supplies a key to a private backend, or (b) accept that portfolio pages stay disabled. This is a decision for the owner, not something a session can work around.
Sources
  • Kalshi help: creating and using a demo account
  • API Keys
Q17 · Where would a private key have to live for trading to be safe? ANSWERED
Not in the browser and not in this repository. Any key placed in a GitHub Pages site is delivered to every visitor; a key pasted into a page is exposed to any script on that origin. Signing must happen server-side, in a component the public cannot read.
Why it matters
Trading requires a backend holding the secret (for example a GitHub Actions job with the key in an encrypted repository secret, or a small server) — a real architecture change, not a front-end tweak.
How to find out
Decide between the Actions-based approach (Suggestion S1) and a hosted backend (Suggestion S5).
Sources
  • API Keys (keep private key secret)
  • GitHub: encrypted secrets
Q18 · What does a trade record contain, so performance can be computed honestly? ANSWERED
A trade has trade_id, ticker, count_fp, yes_price_dollars, no_price_dollars, taker_outcome_side, taker_book_side, created_time and is_block_trade. Fills and positions are portfolio-scoped endpoints requiring authentication. Fees come from the series fee_type and fee_multiplier using Kalshi's published fee schedule.
Why it matters
P&L must subtract fees using the documented fee type per series; a naive price difference would overstate performance.
How to find out
Implemented in the portfolio tabulator; it runs only when authenticated fills exist.
Sources
  • Get Trades (trade fields)
  • Get Series List (fee_type, fee_multiplier)
  • Kalshi fee schedule
Q19 · Can a strategy be recommended from the data we have now? UNKNOWN
Not from demo portfolio data, because there is no demo portfolio. What can be measured without an account is market-level calibration: whether contracts in a given price band resolved YES at the rate the price implied. That is computed on the Analysis page from resolved in-scope markets.
Still missing
Executed trades, fees actually paid, slippage observed, and a period long enough for the calibration sample to be statistically meaningful.
Why it matters
The dashboard distinguishes a market-level observation from a trading recommendation and never presents the first as the second.
How to find out
Sample size and confidence intervals are shown with every calibration band; the decision threshold is a suggestion for review (S3), not a recommendation.
Sources
  • Market settlement
  • Demo caveat

Yes. A request to /exchange/status carrying Origin: https://karagemop466-tech.github.io returned HTTP 200 with access-control-allow-origin: https://karagemop466-tech.github.io, so CORS is reflective and the static site can read public market data directly.
Why it matters

Q21 · How fresh can the published snapshot be, and how do we prove it is not stale? ANSWERED
A GitHub Actions workflow collects every 15 minutes, validates the file, and commits it. The validator refuses to publish a snapshot older than six hours. Every page prints the snapshot time and every row links to its API response.
Why it matters
Freshness is enforced by the build, not promised in prose.
How to find out
Done; the timestamp is on every page.
