Account performance · two modes

Portfolio, trades and outcomes

Two separate things live on this page and are never mixed together. Paper trading needs no credentials and records simulated trades in this browser. Live demo account reads a real Kalshi demo portfolio and sends real demo orders, which requires your own API key. Neither mode ever invents a number.

Why paper trading ships first. A static site cannot hold a private signing key safely — anyone who can load the page can read it. So the default mode is a local simulator that behaves like the real thing for analysis, and the signed mode only runs if you choose to paste a demo key into your own browser. That trade-off is recorded as decision Q-2 on .

Log a paper trade

Pick a ticker from the live console (click a row, then read the ticker under the chart). Price is what you would pay per contract, $0.01–$0.99.

Payout rule used for settlement: a winning contract pays $1.00, a losing contract pays $0.00, so P&L = (result matches side ? count : 0) − price × count. That is the documented binary payout (market settlement) without fees, which are zero for simple yes/no settlement.

Mode B · Live demo account (your key)

Before you paste anything. Use a key created on demo.kalshi.co only — never a production key. The key is sent from your browser straight to external-api.demo.kalshi.co and is kept in sessionStorage for this tab only, so closing the tab drops it. It is never written into the repository. If that is not acceptable, use Mode A.

Credentials

Signing follows authenticated requests: message = timestamp_ms + METHOD + path, RSA-PSS/SHA-256 or Ed25519, base64. Reads used: /portfolio/balance, /portfolio/positions, /portfolio/fills, /portfolio/settlements.

Place a demo order

POST /portfolio/events/orders
This sends a real write to the demo exchange. The legacy POST /portfolio/orders endpoint has been removed and returns 410 Gone; orders now go to the V2 endpoint /portfolio/events/orders with a single-book bid/ask side and fixed-point dollar prices (Create Order (V2)). Market orders are not offered here — limit orders only, so a typo cannot sweep the book.

A 201 means accepted, not resting — always read remaining_count in the response. Every order sends a fresh client_order_id (UUID v4) so a retried request cannot double-fill. Cancel and amend are not wired to buttons yet; see .

Performance is only meaningful once trades settle. The outcome view that joins fills to result lives on Trade analysis; the resolution tracker is on .
