IR-01highSite structureThe repository holds seven separate dashboards built by seven parallel sessions, and the root landing page links to most of them: pages/ with verified/ (14 pages), site/ (14), monitor/ (10), intelligence/ (9), dashboard/ (9), live/ (3) and instrument-panel/site/ (15). Each renders the same five topics with a different layout, so a trader lands on seven different answers to one question.The primary navigation now holds the canonical pages plus the consolidated desk, and the parallel dashboards are grouped on a labelled second row instead of the main bar. Their pages are kept rather than deleted, because each holds independently verified data.evidence
IR-02highSecuritylive/trading.html asks the visitor to paste a Kalshi demo private key (PEM) and API key ID into the page, while portfolio.html in the same repository states in bold: never paste API secrets into this page. The two pages give opposite instructions inside one repository.Flagged for review. This session did not edit live/, which another session owns. The desk pages never request a credential, and the trading page here states the three gates that must open before an order is sent.evidence
IR-03mediumCoordinationPull request #6 removes a browser-side credential form from pages/portfolio.html, but pages/portfolio.html is now generated by tools/build_site.py, so the pull request's hand edit is superseded by the generator and would fail the CI check that regenerates every page and fails on any difference.Flagged for review rather than closed by this session. The generated page already contains no credential form, so the underlying risk is gone; only the stale pull request remains.evidence
IR-04mediumData coverageCulture has two series in scope and no open market in the snapshot, so the culture topic is empty in every dollar ranking. The 20 markets Kalshi files under the Entertainment category are culture-adjacent, not culture, and are held separately rather than reclassified.Stated as empty on the culture page and in the requirements register. No value is borrowed from another topic to fill the gap.evidence
IR-05mediumMetric definitionThe Trade API publishes no dollar-volume field, so the collectors compute an estimate. Two collectors in this repository compute it differently: one sums volume_24h_fp multiplied by last_price_dollars across the child markets of an event, another uses a per-market notional. The same event can therefore carry two different dollar figures depending on which page is read.Every table that shows the estimate also prints the formula and marks the value as computed rather than official.evidence
IR-06mediumAnalysis validityOf 1,601 settled in-scope markets, 1,284 never traded: volume_fp is zero and last_price_dollars comes back as 0.0000, which is a default rather than a price. Calibrating those markets produces a large false edge on long shots.Analysis in this repository restricts calibration to the 317 settled markets that traded. The desk states the traded and never-traded counts on every topic page so the reader can see which set a number came from.evidence
IR-07mediumData pipelineFour collectors write into data/ with different schemas and different refresh schedules: tools/collector.py, tools/collect_kalshi.py, scripts/fetch_data.py and instrument-panel/tools/kalshi_collect.py. Two files in the same directory can disagree about the same market at the same moment.The desk reads the two richest snapshots and states the snapshot time on every page, so a reader can always tell which collection a number came from.evidence
IR-08lowAuditabilityThe source URL of a row is written under four different keys depending on the collector: source, source_url, source_api and src. A checker that only looks for one of them silently passes rows that carry no official source.The verification tool written for this desk accepts all four keys and fails when a row has a value but no official Kalshi URL.evidence
IR-09lowChart honestyThe root dashboard offers a 60-second window, but the tick history it plots is sampled every ten minutes, so that window is legitimately empty and looks broken.The desk chart reads the official trade prints for short windows and the official candlesticks for long ones, and prints the endpoint it used under the chart.evidence
IR-10lowRepository sizedata/dashboard_instrument.json is about 10 MB and is committed again on every refresh, so the working tree grows on every collection cycle.Left in place: the file is the only copy of the data and the workflows rebuild the pages from it. The desk writes a compact summary instead of duplicating the large file.evidence
IR-11lowContinuous integrationThe external link check probes roughly 3,700 unique URLs on every pull request, most of them demo API addresses. Kalshi documents that public endpoints charge the IP address's budget first, so the check itself can trigger rate limiting and make a build flaky for reasons that have nothing to do with the site.Reported rather than changed. The checker already backs off on 429 and treats 403 as reachable, which keeps the flakiness low.evidence
IR-12lowSource of truthThe root index.html and the pages/ directory are generated by tools/build_site.py and tools/build_content.py. Editing the HTML by hand makes the CI step that regenerates every page fail on a difference. This happened on main: the sharp-jump feature was added to index.html, pages/flagged.html, pages/suggestions.html and pages/verification.html by hand, so the build was red on main from the moment it merged.Fixed at the source: the four additions were ported into tools/build_site.py and tools/build_content.py and the pages were regenerated, so the feature is kept and the build is green again. The desk keeps its own generator and does not touch the shared ones.evidence
IR-13lowAuditabilitydashboard/data/snapshot.json cites its sources through identifiers such as S_API_GAS_MARKETS that are resolved through a file-level sources map, and 7 of those identifiers point at the .md variant of a documentation page instead of the HTML page the rest of the site uses. A row audit that only looks for a URL inside the row reports 16 rows of that file as unsourced, and the .md pages are the markdown rendering rather than the documented page.The verification tool resolves both forms, and the .md documentation links were checked by hand and do resolve. The rows are counted as sourced.evidence
IR-14lowContinuous integrationThe strict whole-site checker reports two documentation URLs in instrument-panel/site as unfinished placeholders because the API path templates in them contain a brace that is not preceded by a slash, for example a series query with a category placeholder.Reported, not edited: those pages belong to a merged session and the URLs are documented shapes rather than endpoints that can be opened. The desk pages contain no such template.evidence
